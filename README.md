# _front-html___

Public hub of the owner's HTML front ends.

- `diegonmarcos.github.io/` : git submodule, the GitHub Pages site repo.
- `profile/` : git submodule, `diegonmarcos/diegonmarcos` (the GitHub profile README).
- Every other owner-declared html repo is a submodule too (list: `html-repos.json`; `.gitmodules` is generated from it by `node scripts/gen-gitmodules.mjs`, guard `--check` in CI).
- `pages.json` : every public repo of the owner that publishes GitHub Pages (`repo`, `url`, `source`, `public`).
  Generated by `scripts/gen-pages.mjs` from the GitHub API, never edited by hand. Only public Pages URLs are listed.
- `.github/workflows/pages-drift.yml` : daily (and on push) regenerates `pages.json` and fails when it differs from the committed file.

## Use

    git clone --recurse-submodules https://github.com/diegonmarcos/_front-html___
    GH_TOKEN=... node scripts/gen-pages.mjs          # rewrite pages.json
    GH_TOKEN=... node scripts/gen-pages.mjs --check  # exit 1 on drift

## Consumers

Cloud Browser (Favourites > GH Pages) reads
`https://raw.githubusercontent.com/diegonmarcos/_front-html___/main/pages.json` at runtime and keeps the last good copy as a cache.

## Repos tree (00_repos-tree/)

The hub's own tree of html repos. Same layout as `_git-repos-master/A0_repos-tree`: `00_repos-tree/src/` (input: `filter.json`; the
html.tmpl and md.tmpl are the submodule's), `00_repos-tree/dist/` (outputs: json, md, html with Item List / Table / Canvas views and an
All / HTML / LFS / Others filter, xml, canvas) and the same outputs at the repo root (`repos-tree.*`). There is no list in this repo:
`git-repos-master/` is a git submodule and the tree is its `A0_repos-tree/dist/repos-tree.json` filtered to kind `html`.

    git submodule update --init --remote git-repos-master        # bump the data
    node scripts/gen-repos-tree.mjs            # src -> dist -> root
    node scripts/gen-repos-tree.mjs --check    # drift guard (CI: repos-tree.yml)
    node tests/test-repos-tree.mjs

## Index (index.json, index.html)

`index.html` is an icon grid of every HTML entry point of every **public** sub-repo, grouped by project family, with search,
group filter, light/dark and a mobile layout. Links are relative and assume the parent `git/` folder is the served root
(`../<repo>/<path>`). Private repos (`no_deploy` in `html-repos.json`, e.g. project-pvt-all) are never fetched or listed.

- `index.json`: hand-kept `hub` (the hub's own folder/repo name: the only place to change on a repo rename), `groups`,
  `repos` (title, icon, description, group, `dir`), `overrides` (per `<repo>/<path>`), `exclude`/`include` regexes;
  generated `pins` + `entries`.
- `node scripts/gen-index.mjs --scan` refreshes entries from the pinned gitlinks via blobless depth-1 git fetches
  (trees only, a few MB, no submodule checkout, follows repo renames); `node scripts/gen-index.mjs` renders
  `index.html`; `--check` fails on drift. Entry point = root `*.html` or `index.html` outside src/static/test/node_modules,
  `dist/` preferred, sub-pages under another app's entry collapsed.
- Node, not sh: the repo's generators are already Node, JSON and HTML escaping are native, and the same module is
  imported by the tests (no jq/sed escaping pitfalls, deterministic sorted output).
- `node tests/test-index.mjs`: schema, entry rule, deterministic render == committed file, private exclusion, then a
  temp served tree (only the linked files, read at the pinned SHA) behind a throwaway local server, checked headless
  with Playwright: every card link 200, search, click-through. CI: `.github/workflows/index.yml` (on push and submodule
  bump: rescan, commit, test).
